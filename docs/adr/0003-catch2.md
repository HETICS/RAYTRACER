# 3. Write tests with Catch2

## Context

We work test first. The client wants anomalies traced to a cause and fixed, and the code understood by people who did not write it (see the discovery report): tests have to read like a description of the behaviour. The framework must integrate with CMake and CTest.

Alternatives considered:
- **GoogleTest**: very widespread, but more verbose (fixtures, `EXPECT_EQ` macros).
- **doctest**: very light and fast to compile, but a smaller community.
- **Boost.Test**: complete, but pulls in Boost, a heavy dependency.

## Decision

We use Catch2 v3.7.1, fetched with `FetchContent`. Test names are plain sentences, for example `"a ray parallel to the floor misses it"`. `catch_discover_tests` registers each test case with CTest. Tests live in `tests/`, mirroring `src/`.

## Status

Proposed

## Consequences

- Test names document the behaviour in plain English, which helps a new developer understand the code.
- `REQUIRE` and matchers such as `WithinAbs` keep tests short, including floating-point comparisons.
- Each test case shows up separately in CTest and in the CI output.
- Catch2 v3 is a compiled library, not a single header: the first build takes longer.
- One more dependency to download on the first configure.
